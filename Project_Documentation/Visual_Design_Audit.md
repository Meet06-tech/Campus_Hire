# Visual design audit

Page references in the first column identify the 44-page PDF rendered from the original Word document. The revised A4 edition has 32 pages.

| Original pages | Finding in the rendered pages | Correction in the final edition |
|---|---|---|
| 1 | The title, description and single placeholder occupied the top third. Submission details had no individual fields. | A centered degree and title hierarchy, binding margin, six labeled submission fields and a first-page header/footer exception. The original introductory description appears under Project Profile. |
| 2 | Main chapters and subsections looked alike in a dense three-column grid. | Four-column university index with chapter and subsection numbers, indented subjects, three feasibility subentries and verified page references. |
| 3–5 | Chapter breaks left the bottoms of short chapters empty. Heading sizes and spacing provided little navigation. | Linked heading styles, a teal chapter rule and continuous text across short chapters. |
| 6–7 | Requirement IDs occupied one third of each row. Long descriptions wrapped in a narrow column. | The processing and output column receives most of the width. Header and body rows are visually distinct. |
| 7–9 | Figures and surrounding text competed for space. Captions were small and inconsistently positioned. | Higher-resolution diagrams from editable SVG, centered at the available width, with chapter-numbered captions and linked explanations. |
| 10 | Only the explanation belonging to the previous page’s class diagram appeared here. | The diagram, caption and explanation now appear together on page 9. |
| 11–33 and top of 34 | Repeated keys, SQL checks and equal-width columns made the dictionary hard to scan. Pages 15 and 28 contained particularly tall rows with mostly empty neighboring cells. Continued tables lacked a table identifier. | Combined types and key indicators, moved long checks into numbered full-width notes, and included the relation name in the repeated header. All 241 column names were reconciled in table order. |
| 34–35 | The screen catalogue consisted entirely of text and yellow requests for images. | Three original application captures now illustrate staff login and student sign-in/registration. Six protected screen groups retain explicit placeholders. |
| 35–36 | The reporting caveat appeared by itself on page 36. | The ten report descriptions and their interpretation caveat fit together on page 28. |
| 37–41 | Narrow test-scenario columns and repeated execution instructions obscured differences between cases. | Suite-level execution instructions with wider scenario columns and individual case identifiers and outcomes. Unexecuted system cases remain labeled separately. |
| 42–44 | Three short closing chapters each consumed a page. | Recommendations, references and the internal-guide placeholder share page 32 under separate indexed headings. |

The revised document uses running headers, page-number fields and repeatable table-header rows. Pagination was checked after Word-to-PDF rendering. All 34 index entries resolved to their printed headings; the independently rendered proof and distributed PDF had the same text on each page. The report still requires institutional details, approved protected-screen captures and the internal guide’s report before submission.
